# Agent Team

Harness для облачных LLM и CLI-агентов: спецификация, изолированное исполнение, независимая проверка и слияние с одобрения человека.

## Что это

Agent Team управляет работой агентов обычным кодом.
Код держит права, состояние, число попыток, бюджет, проверку результата и разрешение на слияние.
Модель может ошибаться, поэтому её отчёт не считается доказательством успеха.
Система не зависит от поставщика модели: замена модели или CLI-агента не требует переписывания архитектуры.

Этот репозиторий — рабочее место разработки Agent Team.
Сессия здесь помогает строить систему и не действует как будущий Worker или Architect.

## Состояние

Готово рабочее место: правила для агентов, набор skills, структура документации и скрипты сопровождения.
Кода Harness пока нет.
Границы MVP и открытые вопросы записаны в `docs/context/Agent_Team_Context_v1.1.md`.

## Начало работы

```sh
git clone git@github.com:moonstars007/Agent-Team.git
cd Agent-Team
scripts/link-global-rules.sh
```

Скрипт связывает `docs/agents/writing-rules.md` с `~/.config/opencode/AGENTS.md`.
OpenCode загружает эту ссылку как глобальные правила в каждой сессии.
Запускайте скрипт после клонирования и после переноса каталога.

Другие скрипты:

- `node scripts/sync-skills-lock.mjs .` — пересчитывает хеши в `skills-lock.json`.

Проверок пока нет: они появятся вместе с кодом.

## Правила репозитория

- Читайте `AGENTS.md` перед работой с репозиторием.
- Читайте `SKILL.md` skill перед его применением.
- Храните секреты в локальном `.env`. Документируйте нужные переменные в `.env.example` без значений.
- Кладите файл в `Input/` для разбора и в `Resources/<тема>/` для постоянного хранения.
- Ведите ключевые ссылки в `docs/research/links.md`, черновой список — в `Resources/links.md`.
- Обновляйте инструкции запуска вместе с кодом.
- Skills в `.agents/skills/` совпадают с upstream. Правило проекта живёт в `docs/agents/`, skill получает одну строку-указатель.
