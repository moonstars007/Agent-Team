# Разбор трёх первых коммитов ai-first-platform

Источник: [KirillSachkov/ai-first-platform](https://github.com/KirillSachkov/ai-first-platform).
Локальная копия: `Resources/ai-first-platform` (не коммитится).
Дата разбора: 10 ноября 2026 года.
Разобраны коммиты от 28 октября 2026 года: `d3523c1`, `44c9477`, `dd1a104`.

## Итог

Три коммита задают фундамент процесса, а не продукта.
Первый коммит добавляет требования и правила файлов.
Второй коммит добавляет набор skills и три файла проектных настроек.
Третий коммит удаляет дублирующий файл инструкций.

Главное решение: проект владеет своим harness.
Skills лежат в репозитории копией, а проектные правила живут отдельно от текста skills.

## Решения и причины

Сообщения коммитов короткие. Причину ниже подтверждает текст файлов или более поздний коммит. Вывод без прямого доказательства помечен словом «вывод».

| Решение | Доказательство | Причина |
| --- | --- | --- |
| Начать с требований, а не с кода. | `customer-requirements.md`, фраза README о невыбранном стеке | Заказчик дал проблему и границы. Код без согласованного объёма ведёт к переделкам. Вывод. |
| Настроить правила файлов до появления кода. | `.editorconfig`, `.gitattributes` в первом коммите | Поздняя настройка переформатирует историю и создаёт шум в ревью. Вывод. |
| Один `.gitignore` для будущих стеков. | Записи для Node, Python, Rust, Java, coverage, `.env`, ключей | Стек ещё не выбран. Секреты и мусор исключаются сразу. Вывод. |
| Хранить копию skills в репозитории. | 27 каталогов, 3714 строк, README с версией | Проект владеет своим harness. Версия зафиксирована в Git. Позже README прямо называет это решением владельца. |
| Один каталог skills для всех клиентов. | `.claude/skills` указывает на `../.agents/skills` | Codex и OpenCode читают `.agents/skills`. Claude Code требует свой путь. Копия одна. |
| `AGENTS.md` — единственный вход для агента. | 17 строк с указателями вместо текста правил | Дублирование инструкций расходится между файлами. Позже это подтверждают коммиты #36 и #47. |
| Проектные настройки отделить от шаблонов. | `docs/agents/` — копии шаблонов, шаблоны не тронуты | Активная конфигурация живёт в `docs/agents/`. Шаблоны остаются upstream. |
| Глоссарий назвать `DOMAIN.md`. | Замена имени в `docs/agents/domain.md` | Название выбрано проектом. Вывод. |
| Удалить `CLAUDE.md`. | Коммит `dd1a104`, слово `redundant` | Файл повторял `AGENTS.md` целиком. Одна точка правки. |

### Как эти решения менялись дальше

Позже проект отменил замену имени глоссария.
Коммит #47 переименовал `DOMAIN.md` обратно в `GLOSSARY.md`.
Тот же коммит вернул текст skills к upstream.
Остались только строки-указатели на правила проекта.
Формулировка из сообщения коммита: «Каждое правило процесса теперь имеет один источник в docs/agents/».

Итоговый принцип из `.agents/skills/README.md`:

- Копия skills совпадает с upstream, кроме строк-указателей.
- Таблица адаптаций перечисляет каждое отклонение.
- Проверка синхронизации — `diff -r` против upstream.
